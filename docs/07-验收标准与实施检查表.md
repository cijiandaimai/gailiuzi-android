# 07 验收标准与实施检查表

## 1. 产品验收

### 1.1 组织和账号

- [ ] 可以创建总部、区域和门店。
- [ ] 用户只能查看被授权组织的数据。
- [ ] 一个门店可绑定多个平台账号。
- [ ] 一个平台账号可明确绑定一个或多个门店并配置默认门店。
- [ ] 解绑账号后不再创建新任务。

### 1.2 三模式

- [ ] 前台模式支持发现、分类、草稿、审批、发送/填充和验证。
- [ ] 逛街模式只使用批准的关键词和平台允许的能力。
- [ ] 公关模式支持 P0～P3、证据、负责人、SLA 和完整事件记录。
- [ ] 三个模式可按平台、账号和门店独立开启或关闭。
- [ ] 逛街模式采用“内容初筛 → 候选人公开主页复核 → 上下文回复”的两阶段流程。
- [ ] 作者和评论区访客使用不同的互动策略。
- [ ] 点赞与回复分别决策，不自动成套执行。

## 2. Android 验收

- [ ] 权限按功能渐进申请，并说明用途。
- [ ] 无障碍关闭时 UI 任务不会错误执行。
- [ ] MediaProjection 未授权时正确降级。
- [ ] 用户触摸屏幕后 Agent 暂停。
- [ ] 前台服务通知可暂停任务。
- [ ] App 首页有停止全部操作按钮。
- [ ] 锁屏、验证码、账号验证和异常提示触发停止。
- [ ] 每次发送前校验平台、账号、门店和评论。
- [ ] 发送状态未知时不直接重试。
- [ ] 平台 App 新版本不兼容时可远程关闭写操作。

## 3. 抖音验收

- [ ] OAuth state 校验有效，token 只保存在服务端。
- [ ] 能同步授权账号视频和自有视频评论。
- [ ] 能生成、审批和回复评论并验证结果。
- [ ] 关键词视频只使用审核通过的品牌相关词。
- [ ] API 权限不足时明确展示，不静默切换高风险路径。
- [ ] 解除授权后账号自动停用。

## 4. 美团验收

- [ ] 能识别经营宝当前登录账号和门店。
- [ ] 能定位待回复评价并读取完整内容。
- [ ] 能将草稿准确填入正确评价。
- [ ] 最终发送策略符合部署版本要求。
- [ ] 能识别违规评价投诉入口并生成证据清单。
- [ ] 不提供代用户写评价或竞品评价互动功能。

## 5. 小红书验收

- [ ] 可以发现自有账号评论通知或由用户主动打开目标评论。
- [ ] 能读取评论、生成草稿和显示风险说明。
- [ ] 默认必须由用户确认最终发送。
- [ ] 不后台批量执行点赞、收藏、关注、评论和分享。
- [ ] 公关模式保存的是内部 Mention/Incident，不自动连续互动。

## 6. AI 验收

- [ ] 输出符合 JSON Schema。
- [ ] P0/P1 召回率满足发布门槛。
- [ ] 回复只引用有效、已审核、属于正确门店的知识。
- [ ] 无知识时不编造答案。
- [ ] 评论中的指令不会改变 Agent 动作。
- [ ] 潜客判断列出可观察证据，不输出基于头像的敏感属性推断。
- [ ] 回复生成包含作品、目标评论、父级对话和相邻评论上下文。
- [ ] 过敏、伤害、隐私、退款和医疗内容进入人工审批。
- [ ] 最终回复保存模型、Prompt、知识和规则版本。

## 7. 安全验收

- [ ] 客户端和日志中无平台 `client_secret`。
- [ ] 日志中无完整 token、Cookie、手机号和订单号。
- [ ] 截图上传前完成脱敏。
- [ ] 租户之间无法访问对方数据和对象存储。
- [ ] 设备解绑后证书和会话失效。
- [ ] 高权限后台账号启用 MFA。
- [ ] 所有发送、修改策略和审批操作进入审计日志。
- [ ] 组织和账号级熔断经过演练。

## 8. 性能与稳定性验收

- [ ] API 评论同步延迟达到目标。
- [ ] UI 单条任务耗时达到目标。
- [ ] UI 动作成功率达到目标。
- [ ] 重复发送率达到目标。
- [ ] 错账号发送为零。
- [ ] 后端达到约定可用性。
- [ ] 设备离线后任务不会在其他未授权设备上执行。

## 9. 上线前业务检查

- [ ] 三平台企业主体和测试账号准备完成。
- [ ] 抖音所需 Scope 已申请并记录审批状态。
- [ ] 美团评价接口商务确认已记录；无接口时 UI 边界明确。
- [ ] 小红书社区能力已向官方确认，产品承诺与实际能力一致。
- [ ] 品牌知识、门店信息、活动有效期已审核。
- [ ] 美业违禁词和高风险流程已由业务负责人确认。
- [ ] P0/P1 联系人和夜间告警方式有效。
- [ ] 用户协议、隐私政策、权限披露和数据保留策略准备完成。

## 10. 每次平台 App 升级检查

- [ ] 记录新版本号和发布时间。
- [ ] 在灰度设备安装。
- [ ] 回归登录、账号识别和门店切换。
- [ ] 回归评论列表、详情、输入和发送。
- [ ] 回归验证码和风险提示识别。
- [ ] 比较页面指纹和选择器变化。
- [ ] 达标后扩大灰度；不达标时保持写操作关闭。

## 11. 完成定义 Definition of Done

一个平台功能只有同时满足以下条件才算完成：

1. 产品需求、页面和状态定义完成。
2. 官方能力和平台规则已经核对并留档。
3. API 或 UI 适配实现完成。
4. 单元、契约、金标回放和真机测试通过。
5. 风控、审计、熔断和人工接管可用。
6. 监控、告警、运维手册和回滚方案就绪。
7. 真实授权账号完成灰度验证。
8. 对应验收指标达标并由产品、研发、测试和业务共同签字。
