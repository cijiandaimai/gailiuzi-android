# 11 v0.3 服务行业超级智能体、多门店与多模型网络方案

## 1. 本轮目标

改流子 v0.3 从“手机端评论辅助底座”升级为服务行业口碑经营端，重点覆盖美容、皮肤管理、按摩、推拿、SPA、美发、美甲美睫、医美和健身等行业：

1. 总部—区域—门店三级管理和角色分工。
2. 线上产品评价、线上到店评价与线下服务反馈统一处理。
3. 服务行业合规规则、负面评价升级和人工审核。
4. 商家专属知识库、自动学习、人工修订和纠错训练。
5. 商户自主选择主控模型，推荐 GPT 与豆包，同时支持千问、Gemini、DeepSeek和兼容接口。
6. 在不内置 VPN 的前提下提供直连、企业 API 网关、智能路由和网络诊断。

## 2. 成熟产品能力借鉴

### 2.1 Birdeye

借鉴能力：

- 多站点评价统一收件箱。
- 多门店视角、门店级分析与品牌级汇总。
- AI 根据品牌语气、上下文和守护规则生成回复。
- 负面/紧急评价告警、分派和闭环。
- 评价趋势、响应率和门店横向对比。

落地到改流子：经营页统一展示线上评价与线下反馈；组织范围支持总部、区域和门店切换；回复经过商家知识、话术和合规规则三层约束。

官方参考：

- https://birdeye.com/reviews/
- https://birdeye.com/review-management/
- https://birdeye.com/enterprise/

### 2.2 Podium

借鉴能力：

- 评论、咨询和客户互动进入统一 Inbox。
- AI Reputation Specialist 生成个性化回复。
- 评价邀请与提醒形成自动工作流。

落地到改流子：统一评价收件箱采用“待处理—跟进中—已闭环”状态；模型回复可选择主控模型并自动回退。

官方参考：https://www.podium.com/product/reviews

### 2.3 Yotpo

借鉴能力：

- 商品评价、图片/视频 UGC 和问答集中管理。
- 自动规则与人工审核结合。
- 评价升级到客服或工单系统。
- AI 建议回复允许发送前编辑。

落地到改流子：线上商品评价与到店服务评价共用口碑记录；高风险生成结果强制人工审核；训练样本只能使用商家审核通过的标准答案。

官方参考：

- https://support.yotpo.com/docs/reviews-product
- https://support.yotpo.com/docs/reviews-moderation-1

### 2.4 美团经营宝/商家后台

借鉴能力：商家移动经营入口、门店经营数据、线上门店配置及本地服务场景。

落地到改流子：移动端优先；将门店编码、城市、线上店铺映射和美团/点评授权配置放在同一商户组织模型中。

官方参考：https://e.meituan.com/mobile

## 3. 已实现的产品结构

### 3.1 经营页

- 商家名称、服务行业和当前角色设置。
- 总部、区域、门店组织增删改与当前管理范围切换。
- 关联城市、门店编码和线上店铺名称。
- 统一口碑指标：线上评价、线下反馈、待处理、风险事件。
- 手工录入线下回访、CRM和其他反馈。
- 统一记录来源、评分、情绪、问题分类和处理状态。

### 3.2 合规风控

内置规则：

- 美容、按摩、SPA、医美场景的治疗/治愈/根治/永久有效等功效宣称。
- 100%、最低价、保证有效、零风险等绝对化或价格承诺。
- 手机号和邮箱等个人信息公开泄露。
- 商家自定义禁用词。
- 负面反馈升级及风险回复人工审批。

规则同时进入模型系统提示词，并对生成结果做确定性二次扫描。模型输出不能自行绕过规则。

## 4. 商家超级智能体

### 4.1 知识来源

- TXT、Markdown、CSV、JSON 等文本文件。
- 手工知识条目。
- FAQ 标准问答。
- 人工纠错和优质回复训练样本。

### 4.2 学习流程

```text
上传/编辑资料
    ↓
保存到应用私有目录
    ↓
自动切块并建立本地检索索引
    ↓
调用商户选择的主控模型提炼事实摘要
    ↓
人工复核（可开启或关闭）
    ↓
按总部/区域/门店权限进入回复检索
```

“自动学习”默认采用 RAG，而不是直接修改基础模型参数：原始资料可追踪、可修订、可停用，且更新后立即生效。商家可以编辑正文和 AI 摘要，也可以维护“典型问题—标准答案”作为审核训练样本。

如果商家在模型供应商侧完成 SFT/微调，可在模型配置中直接填写供应商返回的微调模型 ID；后续服务端版本再增加数据集上传、任务状态和评测的正式 API 编排。

### 4.3 范围继承

- 总部通用知识：所有区域和门店可检索。
- 区域知识：该区域及其门店可检索。
- 门店知识：仅该门店可检索。
- 当前门店回复会组合门店、上级区域和总部知识。

## 5. 多模型主控

| 提供商 | 默认协议 | 默认 Base URL | 默认模型 | 说明 |
|---|---|---|---|---|
| GPT / OpenAI | Responses | `https://api.openai.com/v1` | `gpt-5-mini` | 推荐主控 |
| 豆包 / 火山方舟 | Responses | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-2-0-lite-260215` | 推荐主控、大陆友好 |
| 千问 / 阿里云百炼 | Chat Completions | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.7-plus` | 大陆友好、多模态 |
| Gemini | OpenAI-compatible Chat | `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-3.5-flash` | 多模态 |
| DeepSeek | Chat Completions | `https://api.deepseek.com` | `deepseek-v4-flash` | 文本与推理 |
| 自定义 | OpenAI-compatible Chat | 商户填写 | 商户填写 | 可连接 Kimi、GLM、MiniMax 或企业模型网关 |

模型名称和 Base URL 均可编辑，避免供应商版本更新导致应用必须发版。API Key 和企业网关令牌通过 Android Keystore 加密保存。

调用顺序：商户选择的主控模型 → 其他已启用且配置完成的模型。单一提供商失败不会直接中断任务。

官方参考：

- OpenAI：https://platform.openai.com/docs/api-reference/responses
- 火山方舟：https://www.volcengine.com/docs/82379/1958524
- 阿里云百炼：https://help.aliyun.com/zh/model-studio/base-url
- Gemini：https://ai.google.dev/gemini-api/docs/openai
- DeepSeek：https://api-docs.deepseek.com/

## 6. 绿色通道与网络适配

### 6.1 模式

1. **智能路由**：豆包、千问、DeepSeek 等大陆可用模型优先官方直连；其他模型按地区和配置使用企业网关。
2. **全部直连**：直接请求供应商官方 Base URL。
3. **企业网关**：全部请求通过商户自建或已签约的 HTTPS 模型 API 网关。

绿色通道不创建系统 VPN，不接管其他 App 流量，只影响改流子发出的模型 API 请求。

### 6.2 企业网关约定

网关 Base URL 假设为 `https://gateway.example.com`：

```text
POST /providers/{provider}/responses
POST /providers/{provider}/chat/completions
```

请求头：

```text
Authorization: Bearer <模型API Key>
X-Gailiuzi-Provider: openai|doubao|qwen|gemini|deepseek|custom
X-Gailiuzi-Upstream-Base: <供应商官方Base URL>
X-Gailiuzi-Gateway-Authorization: Bearer <企业网关令牌>
```

生产网关需要 HTTPS、请求签名、限流、审计、密钥托管、租户隔离、日志脱敏和健康检查。后续可增加“网关托管模型密钥”模式，避免模型 Key 从手机传入中转层。

### 6.3 地区处理

应用允许商户选择中国大陆、香港/澳门、台湾或其他海外地区，并提供 DNS/HTTP 可达性和延迟诊断。是否允许直连最终按模型供应商实时支持地区、商户账号资格和服务条款判断：

- Gemini 官方可用地区：https://ai.google.dev/gemini-api/docs/available-regions
- OpenAI API 支持地区：https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories
