# 04 AI、知识库、数据模型与接口

## 1. AI 总体设计

大模型不直接接管手机，AI 层由多个受约束步骤组成：

```text
内容清洗
→ 平台/账号/门店归属
→ 意图和情绪分类
→ 风险识别
→ 知识库检索
→ 回复生成
→ 事实一致性检查
→ 违禁词和隐私检查
→ 自动化策略决策
→ 结构化结果
```

不同步骤可使用不同模型。分类和合规优先使用低延迟模型或本地规则，复杂客诉摘要和回复使用能力更强的模型。

## 2. 统一 AI 输出结构

```json
{
  "language": "zh-CN",
  "intent": "PRICE_QUERY",
  "sentiment": "NEGATIVE",
  "urgency": "P2",
  "businessDomain": "SKIN_CARE_SERVICE",
  "storeId": "store_uuid",
  "facts": [
    {"text": "用户称等待40分钟", "source": "comment", "verified": false}
  ],
  "riskTags": ["SERVICE_COMPLAINT"],
  "knowledgeRefs": ["kb_doc_uuid#chunk_12"],
  "replyDraft": "您好，给您带来等待体验不佳……",
  "replyGoal": "ACKNOWLEDGE_AND_COLLECT_ORDER",

  "confidence": 0.93,
  "reasonCodes": ["NEGATIVE_REVIEW", "FACTS_NOT_VERIFIED"]

```

服务端必须用 JSON Schema 校验模型输出；不合格结果不得进入执行器。

## 3. 意图体系

一级意图建议固定枚举：

- `PRAISE`
- `GENERAL_QUESTION`
- `PRICE_QUERY`
- `LOCATION_QUERY`
- `BUSINESS_HOURS`
- `APPOINTMENT_QUERY`
- `PRODUCT_USAGE`
- `PRODUCT_AUTHENTICITY`
- `SERVICE_COMPLAINT`
- `PRODUCT_REACTION`
- `REFUND_REQUEST`
- `PRIVACY_COMPLAINT`
- `INJURY_OR_MEDICAL`
- `HARASSMENT_OR_ABUSE`
- `MEDIA_OR_INFLUENCER`
- `SPAM_OR_IRRELEVANT`
- `OTHER`

标签体系应支持多标签，但必须有一个主意图。

## 4. 风险识别

### 4.1 高风险标签

- 医疗诊断、治疗和保证性功效。
- 过敏、感染、受伤、毁容等人身损害。
- 未成年人。
- 用户手机号、地址、订单号、身份证等隐私。
- 退款、赔偿、法律责任和监管投诉。
- 媒体、达人、律师函、集中投诉。
- 对竞品的贬损、影射或未经证实指控。
- 可能构成骚扰、歧视或人身攻击的回复。

### 4.2 回复决策矩阵

| 情况 | 默认动作 |
|---|---|
| 正面评价、普通咨询、知识充分 | 可进入自动白名单 |
| 轻度负面、事实简单 | 草稿 + 店长确认 |
| 退款/过敏/伤害/隐私 | 创建工单，不自动发送 |
| P0/P1 舆情 | 暂停账号自动回复，由总部审批 |
| 知识库无答案或事实冲突 | 不生成确定性结论，请人工处理 |
| 平台规则或广告风险命中 | 重写；仍命中则阻止发送 |

## 5. 回复生成要求

回复必须满足：

- 先回应用户具体问题，避免泛化模板。
- 不编造订单、门店调查结果、产品成分或效果。
- 不承诺无法兑现的退款、赔偿或疗效。
- 不公开要求用户提供手机号、订单号等敏感信息。
- 优先引导使用平台内私信、订单售后或官方门店入口。
- 负面场景使用“理解 + 已知事实 + 下一步”结构。
- 不与用户争辩，不攻击竞品，不暴露内部责任认定。
- 控制长度，避免每条回复都包含营销信息。

## 7. 知识库设计

### 7.1 层级

```text
行业公共知识
└── 品牌知识
    ├── 产品知识
    ├── 服务项目
    ├── 品牌政策
    ├── 标准话术
    └── 区域知识
        └── 门店知识
            ├── 地址/营业时间
            ├── 停车/交通
            ├── 门店项目与价格区间
            ├── 员工和设备配置
            └── 门店临时公告
```

检索优先级：门店 > 区域 > 品牌 > 行业。下层可以覆盖上层，但必须记录生效时间和审批人。

### 7.2 文档生命周期

```text
DRAFT → REVIEWING → ACTIVE → EXPIRED/REVOKED
```

每段知识保存：

- 来源和原始文件。
- 所属组织/品牌/门店。
- 有效期。
- 审核人。
- 风险等级。
- 可用于哪些平台和意图。
- 是否允许作为自动回复事实。

### 7.3 检索约束

- 门店任务不得检索其他门店的价格和活动。
- 过期活动不能进入回复。
- 未审核知识只能用于内部建议，不能用于自动发送。
- 回复保存引用的知识片段，方便复核。

## 11. 模型与 Prompt 版本管理

每次 AI 结果保存：

- 模型供应商和模型名。
- 模型版本或日期。
- 系统 Prompt 版本。
- 分类标签版本。
- 知识库快照版本。
- 风险规则版本。
- 输入和输出哈希。
- Token、时延和成本。

生产 Prompt 不直接在客户端下发。更新先经过离线回放集测试，再按租户灰度。

## 12. AI 质量评估集

建立脱敏金标集，至少覆盖：

- 三个平台各 1,000 条真实评论。
- 正面、普通咨询、轻度负面、严重客诉。
- 美业医疗功效边界。
- 方言、错别字、表情和反讽。
- 多门店同名、同品牌不同活动。
- 对抗性指令和评论中的 Prompt Injection。

模型不得执行评论文本中的指令；评论始终作为不可信数据处理。

## 13. 潜在客户判断输出

逛街和公关模式使用独立结构化输出：

```json
{
  "actorRole": "POTENTIAL_CUSTOMER",
  "observableSignals": [
    "评论中询问本地门店",
    "公开地区与门店城市一致",
    "近期公开内容与护肤需求相关"
  ],
  "leadPotential": 0.86,
  "topicRelevance": 0.91,
  "replyWorthiness": 0.88,
  "likeDecision": "NO_ACTION",
  "replyDecision": "DRAFT_FOR_APPROVAL",
  "replyAngle": "回答门店位置和预约方式",
  "sensitiveInferences": [],
  "confidence": 0.89
}
```

模型只能输出可观察信号。若结论依赖头像推断人口属性、健康状态、收入或人格，Schema 校验后必须转为 `INSUFFICIENT_EVIDENCE`。
