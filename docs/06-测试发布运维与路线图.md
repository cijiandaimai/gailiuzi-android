# 06 测试、发布、运维与项目路线图

## 1. 测试总体策略

测试分为六层：

1. 单元测试。
2. API 和数据契约测试。
3. AI 离线评估。
4. Android 页面适配器测试。
5. 真实设备端到端测试。
6. 小流量商家试点和生产监控。

## 2. Android 设备矩阵

### 2.1 系统版本

- Android 12、13、14、15、16。
- 首期最低版本建议 Android 12。

### 2.2 厂商

- 小米/Redmi。
- OPPO/一加。
- vivo/iQOO。
- 荣耀。
- 华为：单独验证系统、通知和后台运行差异。
- 三星。

### 2.3 显示环境

- 720×1600、1080×2400、1440p。
- 标准字体和大字体。
- 显示缩放 100%、较大。
- 深色/浅色模式。
- 全面屏、刘海屏和系统导航方式。

### 2.4 平台 App

- 当前正式版。
- 上一个正式版。
- 灰度/新版本测试池。
- 商家版与消费者版按实际业务分别验证。

## 3. 适配器测试

### 3.1 页面金标

每个关键页面保存：

- 脱敏截图。
- Accessibility 节点树。
- OCR 结果。
- 页面类型金标。
- 关键节点位置和期望动作。

适配器提交时跑离线回放，验证页面识别和选择器命中。

### 3.2 合同测试

每个平台适配器必须通过：

- 正确识别账号和门店。
- 能从稳定入口进入目标页面。
- 不在未知页面执行写动作。
- 输入后能校验完整文本。
- 发送前能确认目标评论。
- 发送后能区分成功、失败和未知。
- 验证码和风险提示触发熔断。

### 3.3 破坏性场景

- 网络中断。
- App 被系统杀死。
- 页面加载缓慢。
- 弹窗、升级提醒和权限提示。
- 用户中途触摸屏幕。
- 账号被退出或切换。
- 门店顺序变化。
- 评论被删除、折叠或追加。
- 系统键盘更换。
- 平台 A/B 页面。

## 4. AI 测试

### 4.1 指标

- 意图分类 Macro-F1。
- P0/P1 召回率。
- 自动回复事实准确率。
- 知识引用正确率。
- 违禁词漏检率。
- 人工接受率和平均修改比例。
- 不同平台的语气适配评分。
- 潜在客户候选 `Precision@K` 和无关候选率。
- 公开主页摘要的证据一致性。
- 作者/访客角色分类准确率。
- 上下文缺失导致的不当回复率。
- 敏感属性推断次数。

### 4.2 发布门槛

- P0/P1 漏报率不得高于 2%。
- 事实编造率低于 0.5%。
- 隐私信息自动输出率为 0。
- 金标集回归不能比当前生产版本下降超过 2 个百分点。
- 新 Prompt 必须通过美业敏感场景测试。
- 任何通过头像推断年龄、性别、健康、收入或人格的输出都视为阻断级缺陷。
- 回复上下文必须包含目标评论及父级对话；缺失时只能生成待人工补充草稿。

## 5. 后端测试

- 多租户隔离测试。
- RBAC 越权测试。
- OAuth state、回调和 token 刷新测试。
- 任务幂等和重复投递测试。
- 同账号并发锁测试。
- 数据删除和保留策略测试。
- 对象存储签名 URL 和访问控制测试。
- 审计日志不可缺失测试。
- 限流、熔断和恢复测试。

## 6. 安全测试

- 移动端逆向和本地敏感数据检查。
- 证书、密钥和 token 泄露扫描。
- API 鉴权、重放和越权测试。
- Prompt Injection 和恶意 OCR 文本测试。
- 截图脱敏回归测试。
- 设备解绑后访问撤销测试。
- 供应链和依赖漏洞扫描。

## 7. 发布渠道

### 7.1 内部测试

- CI 构建签名测试包。
- 仅测试租户可用。
- 使用专用测试账号和测试门店。

### 7.2 企业试点

- 企业分发或 MDM。
- 每家试点 1～3 台专用设备。
- 默认 L1 草稿模式。
- 逐个平台开放写操作。

### 7.3 公共商店版

- 提交无障碍权限声明和功能演示。
- 产品页面准确说明数据读取、自动化范围和用户控制方式。
- 把自主决策与执行拆成建议、审批和确定性规则。
- 平台 UI 写操作按审核结果决定是否保留。

## 8. 灰度发布

灰度单位：

```text
内部设备
→ 员工账号
→ 单门店
→ 单区域
→ 5% 租户
→ 25% 租户
→ 全量
```

每阶段至少观察：

- UI 动作成功率。
- 发送状态未知率。
- 人工撤回/投诉率。
- 平台账号异常率。
- 模型接受率。
- P0/P1 告警质量。
- Crash 和 ANR。

## 9. 可观测性

### 9.1 设备指标

- 在线率、心跳延迟。
- App 和系统版本。
- 无障碍/通知/截图权限状态。
- 电量、温度、网络类型和存储空间。
- 任务成功率、平均步骤数和耗时。
- 页面指纹失败率。

### 9.2 业务指标

- 新评论数量。
- 待回复和超时数量。
- 自动/人工处理比例。
- 回复平均时延。
- 负面率和风险分布。
- 各门店问题聚类。
- 舆情事件首次发现和关闭时间。

### 9.3 AI 指标

- 模型调用成功率、时延和成本。
- 草稿接受率。
- 人工修改距离。
- 知识库无答案率。
- 风险规则命中率。

## 10. 告警

| 告警 | 阈值示例 | 动作 |
|---|---|---|
| 平台 UI 成功率下降 | 15 分钟低于 90% | 关闭该适配器写操作 |
| 发送状态未知 | 10 分钟内 ≥2 | 暂停账号 |
| 错账号校验失败 | 任意一次 | 停止设备所有写任务 |
| P0 舆情 | 任意一次 | 电话/短信/企业 IM 告警 |
| OAuth 刷新失败 | 连续 3 次 | 通知重新授权 |
| AI 风险服务不可用 | 任意持续 5 分钟 | 降级为只生成草稿 |

提交代码

## 12. 项目阶段和时间计划

### 阶段 0：调研和账号申请，2～4 周

- 注册企业主体和三平台开发者/服务商账号。
- 申请抖音 OAuth、评论管理和关键词视频权限。
- 与美团确认服务零售评价接口和服务商合作可能性。
- 向小红书确认社区互动开放能力。
- 准备三平台测试账号、门店和内容。

### 阶段 1：底座和抖音 API，4～6 周

- Android 壳、设备绑定、权限向导。
- 后端租户、组织、账号、任务和审计。
- 抖音 OAuth、视频和评论 API。
- AI 分类、知识库和草稿审批。

### 阶段 2：Android 执行引擎和美团，5～7 周

- Accessibility 感知和动作原语。
- 截图/OCR、页面指纹和状态机。
- 美团经营宝评价读取和回复辅助。
- 错门店校验、熔断和真机测试。

### 阶段 3：小红书辅助和公关中心，4～6 周

- 小红书通知、页面定位、评论草稿和人工确认。
- 跨平台关键词、Mention、Incident 和 SLA。
- 舆情报表和告警。

### 阶段 4：试点和商用化，4～8 周

- 3～5 家门店试点。
- 累积金标评论和页面样本。
- 优化适配成功率和模型质量。
- 完成计费、合同、隐私和运维流程。

完整可商用首版预计 5～7 个月；若只做抖音前台模式 MVP，可在 8～12 周形成试用版本。

## 14. 主要里程碑

- M1：设备绑定、权限、任务下发跑通。
- M2：抖音自有评论 API 闭环。
- M3：美团单门店评论辅助闭环。
- M4：小红书草稿和人工确认闭环。
- M5：总部—区域—门店权限和舆情中心完成。
- M6：三平台真实门店试点达到验收指标。
