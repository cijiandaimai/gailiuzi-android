# 16 平台账号安全与误封风险审计

## 1. 审计目标

本轮目标是通过官方接口优先、最小权限、人工审批、安全停机和可审计性降低商家账号的误操作与误封风险。不实现隐藏自动化特征、模拟真人节奏、绕过验证码或规避平台风控。

任何第三方应用都不能保证账号绝对不被限制。可验收的目标是：改流子不在未知、未授权、未审批或平台已发出安全信号时继续出站写操作。

## 2. 代码审计结果

| 审计项 | 原状态 | 处理结果 |
|---|---|---|
| Android UI 写操作 | 未发现 `performAction`、`dispatchGesture`、`ACTION_CLICK` 或 `ACTION_SET_TEXT` 执行代码 | 保持无 UI 自动发布实现 |
| 无障碍事件 | 配置了点击、焦点、互动窗口和非重要视图能力，实际代码未使用 | 移除点击/焦点事件和窗口内容读取能力 |
| 安全页停机 | 抖音和快手部分风险页会修改运行状态，但前台服务未实际停止 | 风险页立即停止前台服务和全部辅助流程 |
| 小红书风险页 | 页面分类已存在，但未进入停机分支 | 接入统一安全停机 |
| 美团风险页 | 无客户端页面指纹 | 对明确的登录、验证、验证码、风险和封禁 Activity 名进行保守停机 |
| 确定性写入 | 自有上下文和显式审批未作为独立必要条件 | 新增两个硬性条件，未满足时只生成草稿 |
| 出站动作总闸门 | 只有互动决策，没有对执行路由和平台安全信号的最终检查 | 新增 `PlatformActionSafetyPolicy` |

## 3. 出站动作总闸门

`PlatformActionSafetyPolicy` 必须在任何发送器、平台 API 或人工交接器之前执行。

### 3.1 立即暂停

检测到以下任一信号时返回 `PAUSE_PLATFORM`：

- 需要重新登录。
- 验证码或二次验证。
- 账号异常、封禁或风险提示。
- 官方 API 返回平台限流。

暂停后不自动重试平台写入，必须由商家在官方 App 或官方开放平台完成处理后重新启动。

### 3.2 永久禁用的无人值守动作

- 点赞。
- 关注或回关。
- 私信。
- 通过 Android 无障碍 UI 自动发布评论。
- 快手和小红书社区评论自动发布。
- 逛街或公关模式对非自有内容自动写入。

### 3.3 唯一可允许的确定性写入

必须同时满足：

1. 前台模式。
2. 自有账号或自有门店内容。
3. 作者、内容、目标评论和父级对话上下文完整。
4. 平台官方写入能力已通过服务端验证。
5. 当前 Token 实际包含所需 Scope。
6. 回复通过内容合规引擎。
7. 商家对本次回复已记录明确审批。
8. 未命中登录、验证、风险、限流、重复内容或商户预算耗尽信号。

## 4. 运行时信号处理

| 信号 | 决策 | 是否自动恢复 |
|---|---|---|
| 登录/验证码/二次验证 | 停止全部辅助 | 否 |
| 账号风险/封禁 | 停止全部辅助并建立安全事件 | 否 |
| HTTP 429 或平台限流码 | 停止对该平台的出站动作 | 否 |
| 未知页面 | 禁止写入，仅保留诊断 | 否 |
| 重复或高相似草稿 | 转人工复核 | 否 |
| 上下文不完整 | 不生成出站写操作 | 否 |

## 5. 发布前验收清单

- [ ] 生产发送器的唯一入口已强制调用 `PlatformActionSafetyPolicy`。
- [ ] 官方 Scope 由服务端校验，不信任手机本地开关。
- [ ] 人工审批记录包含操作人、时间、平台、账号、目标内容和草稿哈希。
- [ ] 平台限流码、Token 失效和 Scope 缺失均转安全停机，不进行写入重试。
- [ ] 未知页面、未知 App 版本和未验证页面指纹默认拒绝写入。
- [ ] 逛街/公关模式没有无人值守社区写操作。
- [ ] 无障碍服务未实现点击、手势、输入或发布。
- [ ] 连续自动化测试覆盖所有安全信号、平台和执行路由组合。
