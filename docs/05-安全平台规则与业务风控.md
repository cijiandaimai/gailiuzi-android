# 05 安全、平台规则与业务风控

## 1. 风控目标

系统必须同时控制五类风险：

1. 错账号、错门店、错评论和重复发送。
2. 平台能力和平台规则不允许的自动化行为。
3. 大模型编造、敏感表达和不当承诺。
4. 平台凭证、用户评论、截图和商家数据泄露。
5. 大规模任务异常导致账号或品牌事故。

## 2. 接入与分发策略

### 2.1 Google Play 版

Google Play 对 AccessibilityService 自动化的当前要求是：普通应用只能围绕狭窄、明确的目的执行确定性、由人定义的自动化；不允许使用无障碍 API 自主发起、规划并执行行为或决策。

因此 Play 版采用：

- 官方 API 为主。
- AI 生成建议，用户或静态规则决定是否执行。
- 显著披露无障碍数据用途并取得明确同意。
- 提供随时暂停、关闭权限和删除数据入口。
- 不把产品声明成残障辅助工具。

### 2.2 企业专用版

- 面向企业自有设备或专用运营设备。
- 可使用 DPC/Device Owner 管理设备健康和应用配置。
- Android UI 操作仍遵循用户授权、平台账号权限和产品规则。
- 企业后台可以统一熔断，但不能隐藏运行状态或阻止用户停用。

## 3. 平台策略摘要

### 3.1 抖音

- 优先申请 OAuth 和评论/搜索相关 Scope。
- 品牌关键词搜索只使用审核通过、与自身业务紧密相关的词。
- 不把通用品类词或竞品词用于自动回复。
- API 写操作必须在授权范围内执行。
- UI 路径只补齐明确的自有账号经营需求。

### 3.2 美团/大众点评

- 评价必须建立在真实消费体验上。
- 不组织虚假评价、不攻击竞品、不替用户写评价。
- 不诱导用户删除或修改真实评价。
- 商家回复用于解释、处理服务问题和提供售后路径。
- 评价投诉必须基于真实证据和平台列明的场景。

### 3.3 小红书

- 公开社区互动默认“草稿 + 人工确认”。
- 不自动批量点赞、收藏、关注、评论或分享。
- 不伪装素人、不隐藏商业关系、不做重复广告评论。
- 若未来获得官方社区 API 或正式合作权限，再按批准范围开放写操作。

## 4. 业务政策引擎

每个动作通过以下决策链：

```text
租户状态
→ 用户与设备权限
→ 平台能力
→ 账号与门店归属
→ 模式和运行时段
→ 内容风险
→ 平台规则
→ 频率与相似度
→ 审批要求
→ 最终允许/等待/拒绝
```

输出统一为：

- `ALLOW_AUTO`
- `REQUIRE_USER_CONFIRMATION`
- `REQUIRE_MANAGER_APPROVAL`
- `ESCALATE_INCIDENT`
- `DENY`

每次决策必须记录 `reasonCodes`。

## 5. 错账号防护

发送前完成四重校验：

1. 平台包名和平台环境正确。
2. 当前登录账号昵称/账号 ID 与任务绑定一致。
3. 当前门店名称、地址摘要和外部门店 ID 一致。
4. 目标评论作者哈希、文本哈希和时间摘要一致。

任何一项不能确认，任务停止并进入人工队列。禁止仅凭屏幕坐标直接发送。

## 6. 频率和重复控制

配置项按平台、账号、门店、动作类型分别生效：

- 每 10 分钟写操作上限。
- 每小时和每天上限。
- 同一内容作者的互动间隔。
- 同一模板的连续使用次数。
- 回复文本相似度阈值。
- 失败重试预算。

互动预算不以“模仿真人、绕过风控”为目标，而以平台允许范围、回复质量和人工处理能力为依据：

- 没有足够上下文，不消耗写操作预算。
- 同一账号不并行执行多个互动任务。
- 点赞、回复、私信分别计算预算，不通过组合动作批量预热账号。
- 人工正在使用手机时，Agent 立即让出前台。
- 平台未公布固定限额时采用保守内部上限，并根据警告、删除率、失败率和投诉率只下调、不自动放宽。
- 公共商店版的自主互动预算默认设为零，发送必须由用户确认或符合已声明的确定性规则。

这些限制用于保障运营质量和防止任务故障，不通过“随机化行为”规避平台检测。

## 7. 熔断规则

立即暂停账号写操作的条件：

- 出现验证码、设备验证或风险警告。
- 登录账号发生变化。
- 连续三次页面指纹失败。
- 连续两次发送状态未知。
- 一小时内失败率超过 10%。
- 平台适配器版本不在已验证范围。
- 收到用户、店长或总部停止指令。
- P0/P1 舆情要求暂停自动回应。

组织级熔断由总部管理员和系统值班人员双权限控制。

## 8. 数据安全

### 8.1 凭证

- 平台 `client_secret` 和 token 只保存在服务端密钥系统。
- Android Keystore 只保存本设备私钥和本产品短期凭证。
- token 加密存储、定期轮换、按 Scope 最小授权。
- 日志永不记录完整 token、Cookie 和 Authorization 头。
- 产品不采集平台账号密码。

### 8.2 传输与存储

- 全链路 TLS。
- 敏感字段应用层加密。
- 对象存储使用租户隔离和短期签名 URL。
- 数据库按租户行级权限或独立 Schema 隔离。
- 管理员操作启用 MFA。
- 高权限操作要求二次确认。

### 8.3 截图处理

- 默认只截取任务所需区域。
- 上传前识别并遮盖手机号、地址、订单号、头像等信息。
- 原始截图尽量本地短期保存。
- 公关证据截图采用独立保留策略并记录哈希。
- 普通调试截图默认 7 天删除，审计摘要按合同期限保留。

## 9. 隐私与数据最小化

- 评论作者使用平台外部 ID 的不可逆哈希或租户内假名。
- 不建立跨平台个人画像。
- 公开主页快照只用于当前机会或舆情任务，并设置短期有效期。
- ID 和头像用于确认账号、区分个人/机构账号及理解公开表达，不用于人脸识别，也不推断敏感人口属性。
- 不把用户评论用于训练公共模型，除非完成合法授权和脱敏流程。
- 用户可查看设备读取的数据类型和最近操作。
- 解绑账号后停止同步；按保留策略删除 token 和不再需要的数据。

## 10. Prompt Injection 防护

平台评论、笔记、用户名和 OCR 文本都是不可信输入。

- 系统 Prompt 明确将外部文本视为数据，不视为指令。
- 评论中的“忽略规则、执行点击、打开链接”等文字不得影响执行器。
- AI 输出只能通过固定 JSON Schema。
- URL、电话号码和外部联系方式单独提取并默认禁止自动执行。
- 执行动作必须来自任务状态机，不来自评论正文。

## 11. 美业内容规则

### 11.1 默认需要人工确认

- 祛斑、祛痘、美白、修复、抗衰等功效承诺。
- 疾病、诊断、治疗、处方、药物或医疗器械相关内容。
- 过敏、感染、疼痛、破损和其他身体反应。
- 整形、注射、侵入性操作或医疗美容项目。
- 退款、赔偿、责任认定。
- 未成年人服务。

### 11.2 禁止自动生成的表达

- “保证有效”“百分百”“彻底解决”“永久”等绝对化承诺。
- 未经证实地把问题归因于用户肤质或操作不当。
- 对用户身体情况做诊断。
- 公开披露消费记录、联系方式和健康信息。
- 诱导用户删除差评后才提供售后。

## 12. 审批与责任链

| 内容 | 最低审批角色 |
|---|---|
| 普通咨询 | 自动白名单或运营人员 |
| 轻度负面 | 店长 |
| 退款/产品反应 | 店长 + 客服负责人 |
| P1 舆情 | 区域负责人 + 公关负责人 |
| P0 舆情 | 总部公关/法务授权人 |
| 修改全局违禁词和自动发送策略 | 总部管理员 |

审批记录包括原评论、模型草稿、人工修改差异、审批人、时间和最终发送结果。

## 13. 安全事件响应

事件等级：

- S0：凭证泄露、跨租户数据、批量错误发送。
- S1：单租户多账号异常、平台集中限制、重大隐私泄露。
- S2：单账号错发、任务重复、截图脱敏失败。
- S3：普通适配失败或模型质量问题。

S0/S1 自动执行：停止写任务、撤销设备会话、冻结相关 token、保存证据、通知值班人员和租户管理员。
